# Paper indexing

This document is the specification for **phase 2, step 2.2.4** of the Topic brief generation workflow in [README.md](../../README.md).

This step maintains the **PostgreSQL full-text search document** on each ingested `Paper` so [Papers search](papers-search.md) can match topic facet concepts against local papers.

v1 **DDL and ORM mapping are not applied yet**. The search-document contract below is **locked**. There is no Streamlit page and no Prefect job for this step.

**Parent group:** [Paper Ingestion](2.2-paper-ingestion.md). Phase landing: [External sources ingestion](2-external-sources-ingestion.md).

For the application runtime stack, see [technology-stack.md](../technology-stack.md). Query rules: [Papers search](papers-search.md). Keyword JSON shape: [Fulfill papers metadata](2.2.2-fulfill-papers-metadata.md).

## Glossary

| Term | Meaning |
| --- | --- |
| **Paper indexing** | Leaf step that defines and maintains the local search document on `Paper` for [Papers search](papers-search.md). |
| **`keywords_tsv`** | `tsvector` column on `papers`. Tokens come from `source_record.indexing.keywords`. Each keyword string is a search term. |
| **Search document** | The indexed text Postgres uses for `@@` match. v1 is `keywords_tsv` only. |

## Scope

### In scope (current v1)

- Add `Paper.keywords_tsv` (`tsvector`) generated from `source_record` JSONB path `indexing.keywords`.
- Add a GIN index on `keywords_tsv`.
- Map `keywords_tsv` on the existing SQLAlchemy `Paper` model (`DeclarativeBase`) so Papers search can query it without raw SQL.
- Keep this step **out** of the External sources ingestion UI stepper until a page exists (none in v1).

### Out of scope (v1)

- A Streamlit page, domain package, or Prefect flow for indexing.
- Application-maintained or trigger-maintained tsvector (the generated column stays in sync when `source_record` is written).
- A typed promote column for the keyword list (do not duplicate `indexing.keywords` as `TEXT[]` / JSON for search).
- Papers search query behavior ([papers-search.md](papers-search.md)).
- Attaching References ([Add reference](3.2-add-reference.md)).
- Indexing MeSH headings, title, abstract, or full text.
- Extra search engines or Python FTS libraries.

## Search document (locked)

Postgres updates `keywords_tsv` when `inform_source_record` writes `source_record`. No extra write in Python.

| Property | Value |
| --- | --- |
| Table / column | `papers.keywords_tsv` |
| Type | `tsvector`, nullable |
| Text-search config | `simple` (do not use `english` stemming) |
| Source path | `source_record -> 'indexing' -> 'keywords'` (JSONB array of strings) |
| Generator | `jsonb_to_tsvector('simple', coalesce(source_record->'indexing'->'keywords', '[]'::jsonb), '["string"]')` stored generated column |
| Index | GIN on `keywords_tsv` (`ix_papers_keywords_tsv`) |
| Empty / missing keywords | Empty tsvector; Papers search does not match that paper on keywords |

Alembic owns the `GENERATED ALWAYS AS … STORED` expression and the GIN index. Do **not** put that Postgres expression in SQLAlchemy `Computed()` on the mapped class: unit tests create tables with in-memory SQLite, which cannot compile `jsonb_to_tsvector`.

On `Paper`, map `keywords_tsv` as `TSVECTOR` with a SQLite variant of `Text`, nullable, no `Computed`. Declare the GIN index in `__table_args__` with `postgresql_using="gin"` (SQLite ignores that dialect option).

Do not use a subquery over `jsonb_array_elements_text` in the generated column (not allowed). `jsonb_to_tsvector` with filter `["string"]` is the built-in way to index only JSON strings in that array.

Later fields (MeSH, title, abstract) may add weighted `setweight(...) || …` into one column or extra `*_tsv` columns. That change belongs in this spec, not in Papers search.
