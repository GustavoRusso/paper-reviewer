# Show references

This document is the specification for **phase 3, step 3.1** of the Topic brief generation workflow in [README.md](../../README.md). The page and phase chrome exist. Listing References from the database is not built yet (empty state always).

Phase landing: [References selection](3-references-selection.md). Add path: [Add reference](3.2-add-reference.md).

## Glossary

| Term | Meaning |
| --- | --- |
| **Show references** | References selection step 3.1: list papers already selected as **References** for the current `TopicScope`. |
| **Reference** | Durable many-to-many link from one `TopicScope` to one ingested `Paper`. One Topic scope has many References; one Paper may be a Reference for many Topic scopes. Unique on `(topic_scope_id, paper_id)`. Distinct from a **bibliographic reference** and from the UI caption **Reference id**. |

## Scope

### In scope (current v1)

- Reserve the step name, number, and UI contract.
- Require `topic_scope_key`; load the `TopicScope`.
- List Papers that are already References for that Topic scope (identity and display fields owned by Paper / Paper archiving).
- Empty state when the Topic scope has no References yet.
- Page_link to **Add reference** (3.2) to grow the list.
- Page_link back to **Topic scope** and the phase landing (pass `topic_scope_key`).
- Shared References selection phase header/stepper ([3-references-selection.md](3-references-selection.md)).

### Out of scope (v1)

- Running [Papers search](papers-search.md) or attaching new References (owned by [3.2](3.2-add-reference.md)).
- Removing a Reference (not specified for v1).
- Topic-brief drafting.
- Creating or mutating `Paper` rows.

## Reference association (product rules)

| Rule | Detail |
| --- | --- |
| Cardinality | Many-to-many: Topic scope ↔ Paper via Reference. |
| Uniqueness | At most one Reference row per `(topic_scope_id, paper_id)`. |
| Identity | Attach by durable ingested `Paper` (DOI / paper id rules owned by [Paper archiving](2.2.1-paper-archiving.md)). Do not invent a second paper identity for References. |
| Ownership | `Paper` stays global. The Reference link is scoped to the Topic scope. |

## Streamlit UI (v1)

Module: `paper_reviewer.ui.show_references` with `render_show_references()`.

| Property | Value |
| --- | --- |
| `key` | `show_references` |
| `title` | Show references |
| `url_path` | `show-references` |
| `in_sidebar` | false ([ui-style.md](../ui-style.md)) |

### Page behavior

1. Require `topic_scope_key`. Missing key → empty state + page_link to **Topic intake** and **Topic scope**.
2. Show the References selection phase header; then `st.header` **Show references**.
3. When References exist: list each linked Paper (at least title and DOI when present).
4. When none exist: empty-state caption that this Topic scope has no References yet.
5. Page_link to **Add reference** (`add_reference`) so the user can select more papers.
6. Page_link to **Topic scope** (and optional link to the phase landing).

Entry from the phase landing: [References selection](3-references-selection.md).
