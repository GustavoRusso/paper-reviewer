# Show references

This document is the specification for **phase 3, step 3.1** of the Topic scope workflow in [README.md](../../README.md).

Phase overview (docs-only chrome): [References selection](3-references-selection.md). Add path: [Add reference](3.2-add-reference.md).

## Glossary

| Term | Meaning |
| --- | --- |
| **Show references** | References selection step 3.1: list papers already selected as **References** for the current `TopicScope`. |
| **Reference** | Durable many-to-many link from one `TopicScope` to one ingested `Paper`. One Topic scope has many References; one Paper may be a Reference for many Topic scopes. Unique on `(topic_scope_id, paper_id)`. Distinct from a **bibliographic reference** and from the UI caption **Reference id**. |

## Scope

### In scope (current v1)

- Require `topic_scope_key`; load the `TopicScope`.
- List Papers that are already References for that Topic scope (identity and display fields owned by Paper / Paper archiving).
- Empty state when the Topic scope has no References yet.
- Page_link to **Add reference** (3.2) to grow the list.
- Page_link back to **Topic scope** (pass `topic_scope_key`).
- Shared References selection phase header/stepper ([3-references-selection.md](3-references-selection.md)).
- Persist the Reference link in `topic_references` (this step owns the table).

### Out of scope (v1)

- Running [Papers search](papers-search.md) or attaching new References (owned by [3.2](3.2-add-reference.md)). The create helper exists for tests and for later attach; this page does not mutate References.
- Removing a Reference (not specified for v1).
- Topic brief generation (owned by [Topic brief generation](4-topic-brief-generation.md)).
- Creating or mutating `Paper` rows.

## Reference association (product rules)

| Rule | Detail |
| --- | --- |
| Cardinality | Many-to-many: Topic scope ↔ Paper via Reference. |
| Uniqueness | At most one Reference row per `(topic_scope_id, paper_id)`. |
| Identity | Attach by durable ingested `Paper` (DOI / paper id rules owned by [Paper archiving](2.2.1-paper-archiving.md)). Do not invent a second paper identity for References. |
| Ownership | `Paper` stays global. The Reference link is scoped to the Topic scope. |

## Persistence

Postgres `topic_references` rows are the source of truth for which Papers are References for a Topic scope.

### `topic_references` table

Foreign keys: `topic_scope_id` → `topic_scopes.id`; `paper_id` → `papers.id`. Follow the stack rule: **no** `ON DELETE CASCADE` ([technology-stack.md](../technology-stack.md)).

| Column | Type | Description |
| --- | --- | --- |
| `id` | PK | Private row id. Not used in URLs ([dev-practices.md](../dev-practices.md#identifier-naming-id-vs-key)). |
| `created_at` | timestamptz | When the Reference was attached. List sort key. |
| `topic_scope_id` | FK | Owning `TopicScope`. |
| `paper_id` | FK | Linked global `Paper`. |

No minted `key`. No `position` or notes.

Unique: `(topic_scope_id, paper_id)` named `uq_topic_references_topic_scope_id_paper_id`.

ORM: `paper_reviewer.models.topic_scope.reference.Reference`. Thin helpers: `create_reference(session, topic_scope_id, paper_id)` and `list_references_for_scope(session, topic_scope_id)` (join `Paper`, order `created_at` then `id`). Caller owns commit.

### Public list API

Package path: `paper_reviewer.topic_scope.show_references`.

```text
list_show_references(session, topic_scope) -> ShowReferencesResult
```

| Argument | Type | Role |
| --- | --- | --- |
| `session` | SQLAlchemy `Session` | Read. **Caller owns commit.** |
| `topic_scope` | `TopicScope` | Scope whose References to list. |

`ShowReferencesResult.papers` is a list of `ReferencedPaper`: `title`, `url`, `doi`, `authors`, `journal`, `published_year`, `referenced_at` (Reference `created_at`), `paper_brief_available`. Do not reuse the Paper-archiving Pydantic `Paper` type (that `created_at` is archive time; it also carries source handle fields this page does not show).

`paper_brief_available` is `true` only when a global `PaperBrief` row exists for that Paper and `PaperBrief.status` is `succeeded`. No row, or any other status (`not_started`, `failed`, `unavailable`), is `false`. Do not put private `Paper.id` on the card. Brief ownership: [Generate paper brief](2.2.3-generate-paper-brief.md).

Sort: `referenced_at` ascending, then Reference `id` for ties. No pagination in v1.

## Streamlit UI (v1)

Module: `paper_reviewer.ui.show_references` with `render_show_references()`.

| Property | Value |
| --- | --- |
| `key` | `show_references` |
| `title` | Show references |
| `url_path` | `show-references` |
| `in_sidebar` | false ([ui-style.md](../ui-style.md)) |

### Page behavior

1. Require `topic_scope_key`. Missing key, non-UUID value, or no `TopicScope` row → empty state + page_link to **Topic intake** and **Topic scope**.
2. Show the References selection phase header; then `st.header` **Show references**. Do **not** repeat the Reference-id caption (the header already shows it).
3. Load with `list_show_references`. When References exist: for each `ReferencedPaper`, title as a content link to `url`; caption `authors · journal · year · DOI` (em dash when authors/journal/year are missing); then, when `paper_brief_available`, `st.page_link` **Read paper brief** to the Paper brief page (pass `doi` and `topic_scope_key`; [paper-brief.md](paper-brief.md), [ui-style.md](../ui-style.md#topic-scope-key-in-the-url)); when not, `st.badge` **Paper brief not available** (`color="orange"` — Streamlit warning/caution colour).
4. When none exist: empty-state caption that this Topic scope has no References yet.
5. Page_link to **Add reference** (`add_reference`) so the user can select more papers (empty and populated).
6. Page_link to **Topic scope**.

Entry from the Topic scope hub: [Topic scope hub](topic-scope-hub.md). Phase chrome: [References selection](3-references-selection.md).
